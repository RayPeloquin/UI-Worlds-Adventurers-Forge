# Development roadmap

The repository is a tabletop design snapshot. These steps describe future work rather than implemented capabilities.

| Stage | Present status | Evidence needed to advance |
| --- | --- | --- |
| Consolidated rules and opening scene | v0.3 drafted; example calculations desk-checked | Record versioned changes and retain the scene specification. |
| Human tabletop playtest | Not yet run | Completed feedback and scene records from actual participants. |
| Revised game loop | Pending playtest | Evidence that choices, costs, pacing, and appeals work at a human table. |
| Authoritative software state | Design requirements only | Validated resource transactions, scene clocks, versioned records, and reproducible saves. |
| Familiar information permissions | Design requirements only | Isolation enforced before context assembly; tests for cross-player IDs, retrieval, summaries, exports, and secret-bearing sources. |
| Technical computation tools | No application integration | Unit-aware calculations with explicit assumptions, model scope, unknowns, and failure handling. |
| U.I. narration and companions | Proposed | Human choice retained, proposed state changes verified, and unsupported technical claims rejected. |
| Multiplayer software playtest | Future | Session reconstruction, permission tests, correction history, and participant feedback. |
| D&D/SRD adapter | Future option | A defined conversion and any required notices for the exact material incorporated. |

The base design includes all five familiar specialties and equal access to decisive rules, computations, and challenges. Optional presentation or personality must preserve that parity.
